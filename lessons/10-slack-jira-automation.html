Slack과 Jira 자동으로 잇기

문의는 버튼 하나로 이슈가 되고, 관리가 끝나면 사후 연락 날짜가 알아서 잡힙니다

⌨️ 방향키·스페이스로 이동 · N 강사 노트 · D 어둡게

[0~2분] 7회차 "트리거 → 액션" 문장을 다시 떠올리게 하기. 오늘 처음으로 "앱과 앱 사이"를 잇는 날. 수업 전 강사 확인: Jira Cloud for Slack 앱 설치 화면, Jira Automation "Send Slack message"·"Edit issue" 액션 화면, 스마트 값 {{now.plusDays(3)}}가 기한 칸에 들어가는지, 현재 자동화 사용량 화면 위치.

지난 시간 결과물 확인 5분

Jira BOM 보드를 열어 아래 3가지를 확인하세요. 오늘 자동화의 기준이 됩니다.

  • 보드 칸 이름이 정확히 "관리 완료"(띄어쓰기 포함)로 되어 있다
  • 이슈 유형 "예약", "문의", "클레임"이 있다
  • Slack 워크스페이스에서 내가 관리자(소유자)다
칸 이름이나 유형 이름이 다르면 규칙이 작동하지 않습니다. 지금 맞춰 주세요.
3일 동안 보드를 실제로 써 본 수강생에게 "어디가 불편했나" 1명만 듣기. 대부분 "관리 완료 칸에 카드가 쌓이는데 사후 연락을 언제 해야 할지 모름" → 오늘 해결.

자동화 규칙 = 관리실의 "완료 벨" 🛎️ 7분

관리가 끝나면 관리사가 데스크에 벨이나 신호를 보내죠. 데스크는 관리실을 계속 들여다보지 않아도 됩니다. 오늘은 Jira 보드의 "관리 완료" 칸에 벨을 달고, 그 벨이 울리면 사후 연락 날짜를 달력에 적고 Slack에도 알리게 합니다.
자동화 규칙 (Rule)
Jira 안의 "언제 ~하면(트리거) → 만약(조건) → ~한다(액션)" 한 세트
스텝 (Step)
규칙이 실행될 때 트리거·조건·액션이 각각 한 번 돌 때마다 1개씩 세는 사용량 단위
Incoming Webhook URL
Slack 채널의 "우편함 주소". 이 주소로 보내면 그 채널에 메시지가 올라감
시나리오 (Scenario)
Make에서 만드는 자동화 한 개 (보너스에서 사용)
새 용어 4개. 웹훅은 7회차의 "초인종"인데, 이번엔 우리가 Slack의 초인종(우편함)을 누르는 쪽이라고 설명. 스텝은 슬라이드 10에서 계산하며 익힘.

실습 1 · Jira Cloud for Slack 앱 설치 10분

  1. Slack 사이드바 더 보기(More) → 앱(Apps) → "Jira Cloud" 검색
  2. Jira Cloud(Atlassian 공식) → Slack에 추가(Add to Slack) → 허용
  3. 앱 메시지 탭의 안내대로 Jira 사이트(bomnal) 연결 → Atlassian 로그인
  4. #예약 채널에서 /jira connect 입력 → 프로젝트 BOM 선택
  5. 알림 설정에서 "상태가 바뀔 때" 정도만 켜기 (너무 많이 켜면 시끄러움)
Atlassian 공식 앱이며 무료입니다. Slack 무료 플랜은 앱 10개까지라 자리를 확인하세요.
/jira connect 알림만으로도 "칸이 바뀌면 알림"이 어느 정도 됩니다. 아래 규칙은 사후 연락 기한을 자동으로 잡거나, 원하는 문구·채널로 보내고 싶을 때 씁니다.

앱 이름·명령어·메뉴는 2026-10 기준. 수업 전 확인.

막히는 곳: 관리자 승인 필요(수강생이 소유자가 아니면) → 지난 과제에서 확인. Atlassian 계정이 Slack과 다른 메일 → 같은 메일로 로그인. 예상 질문: "알림 구독도 자동화 한도를 쓰나요?" → 앱 알림은 Automation 규칙이 아니라 한도와 별개로 알려져 있음(수업 전 확인).

실습 2 · #문의 메시지를 버튼 하나로 Jira 이슈로 7분

  1. #문의에 연습 메시지 올리기: "손님이 토요일 오후에 2명 같이 관리 가능한지, 주차 되는지 물어봐요"
  2. 메시지에 마우스 → ⋯ (더 보기) → 이슈 만들기(Create issue) · Jira Cloud
  3. 프로젝트 BOM, 유형 문의, 요약 확인 → 만들기
  4. 메시지 스레드에 이슈 링크(BOM-○)가 달렸는지 확인
  5. Jira 보드 "접수" 칸에 카드가 생겼는지 확인
/jira create 명령으로도 만들 수 있습니다.
AI가 요약·설명을 미리 채워 주는 화면이 나올 수 있습니다. 그대로 저장하지 말고 손님 개인정보·건강정보가 들어갔는지 확인하세요.
메뉴 이름은 "작업 항목 만들기(Create work item)"로 보일 수도 있음. 2~3명이 성공하면 바로 다음으로. 답변 내용 복습: 주차 불가 → 인근 공영주차장 안내, 2인 동시 관리는 관리사 2명 시간이 맞아야 하므로 민호가 확인.

템플릿 라이브러리에도 Slack 알림 템플릿이 있음을 보여 주되, 오늘은 직접 만든다. 감사 로그 위치를 꼭 보여 주기. "3일 뒤에 알림"이 아니라 "지금 3일 뒤 날짜를 기한에 적어 둔다"는 차이를 강조(슬라이드 8 주의 상자).

실습 3 · 규칙 ① "관리 완료 → 3일 뒤 사후 연락" 14분

  1. [Slack 우편함 만들기] api.slack.com/apps → Create New App → From scratch → 이름 "봄날 알림", 워크스페이스 선택
  2. Incoming Webhooks → 켜기(On) → Add New Webhook → #예약 → 허용 → URL 복사
  3. [Jira 규칙] 프로젝트 설정 → 자동화 → 규칙 만들기
  4. 트리거: 이슈 전환됨(Issue transitioned) → 대상 상태: 관리 완료
  5. 조건: 이슈 필드 조건 → 이슈 유형 = 예약
  6. 액션 ①: 이슈 편집(Edit issue) → 기한(Due date)에 {{now.plusDays(3)}}, 담당자 = 민호
  7. 액션 ②: Slack 메시지 보내기(Send Slack message) → 웹훅 URL → 오른쪽 문구
  8. 이름 "관리 완료 → 사후 연락" → 켜기(Turn on) → 카드 하나를 관리 완료로 옮겨 테스트
💆 관리 완료! {{issue.key}} {{issue.summary}}
📞 사후 연락: {{now.plusDays(3).format("MM/dd")}}까지 @민호 실장
(피부 상태 확인 · 다음 예약 안내)
웹훅 URL = 비밀번호. 이 주소만 있으면 누구나 #예약에 글을 올릴 수 있습니다. 채팅방·스크린샷에 올리지 말고, 새 나가면 Slack 앱 설정에서 삭제 후 새로 만드세요.
"3일 뒤에 새 이슈 만들기"는? Jira의 지연(Delay) 액션은 Premium 이상 플랜 전용이고 최대 60분까지만 기다릴 수 있어 3일은 안 됩니다. 그래서 무료 플랜에서는 지금 기한을 3일 뒤로 적어 두는 방법을 씁니다.

메뉴 이름은 2026-10 기준("이슈"가 "작업 항목"으로 보일 수 있음). 지연 액션의 플랜·최대 시간, 웹훅 입력 방식은 화면에 따라 다를 수 있어 수업 전 확인.

가장 오래 걸리는 실습. 막히는 곳: api.slack.com 화면이 영어 → 강사 화면 크게. 대상 상태를 안 고름(모든 전환에 알림). {{ }} 중괄호 오타. 기한 칸에 스마트 값이 안 들어가면 "고급 필드 편집(More options → JSON)" 화면이 필요할 수 있음(수업 전 확인). 월요일 휴무: 관리 완료가 금요일이면 3일 뒤가 월요일 → 민호가 화요일로 직접 바꾸는 규칙으로 충분. (plusBusinessDays는 토·일을 빼는 기능이라 우리 샵 휴무와 맞지 않음) 정말 "3일 뒤 새 이슈"가 필요하면: 매일 아침 한 번 도는 "예약(Scheduled) 트리거 + JQL"로 '관리 완료이고 기한이 오늘인 카드'를 찾아 이슈를 만드는 방법이 있음. 무료 플랜 사용 가능 여부와 매일 쓰는 steps는 수업 전 확인. 빨리 끝난 수강생: 문구에 링크 {{issue.url}} 추가.

실습 4 · 규칙 ② "클레임이 생기면 원장에게" 8분

  1. Slack 앱 "봄날 알림"에서 웹훅을 하나 더: 채널 #cs-escalation
  2. Jira 새 규칙 → 트리거: 이슈 생성됨(Issue created)
  3. 조건: 이슈 유형 = 클레임
  4. 액션 ①: 이슈 할당(Assign issue) → 한봄(원장)
  5. 액션 ②: Slack 메시지 보내기 → #cs-escalation 웹훅 → 오른쪽 문구
  6. 이름 "클레임 알림" → 켜기 → 클레임 이슈 하나 만들어 테스트
🚨 새 클레임 {{issue.key}} — {{issue.summary}}
담당: 원장 한봄 / 오늘 안에 직접 통화해 주세요.
환불·보상은 통화 전 약속하지 않기, 피부 트러블이면 피부과 진료 권유.
규정 복습: 24시간 전까지 무료 변경·취소, 이후 취소·노쇼는 예약금 환불 불가(회원권 1회 차감). 회원권 환불은 이용 횟수를 정가로 빼고 남은 금액에서 위약금 10%를 뺀 뒤 — 계산·처리는 원장이 직접 합니다.
#cs-escalation은 13회차 봇도 쓰는 채널. 원장 휴대폰에 "모든 메시지" 알림이 켜져 있는지 확인(8회차). 할당되면 Jira가 원장에게 메일 알림도 보냄. 관리 후 붉어짐·트러블 호소는 "진단·치료" 표현 없이 공감 → 원장 연결 → 필요 시 피부과 진료 권유가 원칙.

계산 연습 · 무료 150 steps로 충분할까? 8분

봄날 에스테틱 (한 달 26일 영업)steps
규칙 ①: 관리 하루 8건 완료 × (트리거1 + 조건1 + 액션2)8 × 4 = 32 / 일
규칙 ②: 이슈 하루 11건(예약 8 + 문의 3) 생성마다 트리거1 + 조건1 (클레임일 땐 액션 +2)약 22 / 일
한 달 합계약 (32 + 22) × 26 = 1,404
Free 한도 (사이트 전체)150 / 월 → 3일이면 바닥
한도에 닿으면 그 달 남은 기간 동안 모든 규칙이 멈춥니다. 조건이 맞지 않아 아무 일도 안 해도 트리거·조건은 셉니다.

💡 해결 방법

  • 단순 알림은 /jira connect 앱 알림으로
  • 규칙은 정말 중요한 것(사후 연락 기한, 클레임)만
  • Standard: 사용자당 400 steps (4명 = 1,600)

2026-10 기준: Free 월 150 / Standard 사용자당 400 / Premium 750 steps. 유료 플랜 초과분은 2026-12-03부터 1,000 steps당 $0.50. 계산은 단순화한 예시입니다.

수강생에게 자기 샵 숫자(하루 관리·문의 건수)로 직접 계산하게 하기. 정확한 계산보다 "알림 하나에도 사용량이 든다"는 감각이 목표. 무료로 버티는 방법: 규칙 ①에서 Slack 액션을 빼면 8 × 3 = 24/일 → 그래도 무료로는 부족. 무료 플랜이면 "규칙 ②(클레임)만 켜고 사후 연락 기한은 민호가 직접 입력"이 현실적. 사용량 확인: 자동화 화면의 사용량(Usage) 탭. 규칙 ①은 "전환됨" 트리거가 다른 칸 이동 때도 돌 수 있어 실제는 더 많을 수 있음.

왜 Make?

Slack·Jira 밖의 앱(구글 폼, LINE)을 이을 때 씁니다. 자동화 사다리 L3. 13회차 상담봇도 Make로 만듭니다. 시간 예약 자체는 계속 네이버 예약으로 받습니다.

자주 겪는 문제 4분

이럴 때이렇게
규칙이 안 돈다규칙이 켜짐인지, 감사 로그(Audit log)에 기록이 있는지 확인
로그에 "조건 불일치"칸 이름 "관리 완료", 유형 이름 "예약" 철자·띄어쓰기 확인
기한이 안 바뀐다"예약" 유형 화면에 기한(Due date) 필드가 있는지 확인(9회차 실습 4)
Slack에 메시지가 안 온다웹훅 URL을 끝까지 복사했는지, 채널이 맞는지 확인
메시지에 {{issue.key}}가 글자 그대로 나온다중괄호 개수·띄어쓰기 오타 확인
갑자기 모든 규칙이 멈췄다자동화 사용량 확인 → 이번 달 한도 도달. 덜 중요한 규칙 끄기
자세한 대응은 materials/troubleshooting.html 참고.
