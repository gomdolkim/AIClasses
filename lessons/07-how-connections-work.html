지난 시간 결과물 확인 5분

6회차에 만든 샵 홈페이지 링크를 옆 사람과 바꿔서 열어 보세요.

  • 휴대폰에서도 잘 보이나요?
  • 메뉴·가격·위치, 네이버 예약 버튼, LINE 버튼이 있나요?

🤔 그런데…

예약은 네이버로, 문의는 LINE·인스타 DM·전화로 흩어져 들어옵니다. 이걸 누가, 어떻게 팀 전체에 알릴까요?

오늘의 질문은 이것입니다. "프로그램과 프로그램은 어떻게 서로 말을 걸까?"
링크가 안 열리는 수강생은 아티팩트 공유 설정 확인(6회차 복습). 예약 버튼이 네이버 예약 페이지로 제대로 가는지만 같이 눌러 보고, 시간 끌지 말고 "그런데…" 질문으로 넘어가기.

💡 목표

프로그램끼리 직접 전달하게 만들면, 사람은 고객의 피부에 집중할 수 있어요.

주황색 칸(사람이 하는 일)을 손가락으로 짚으며 "이게 다 옮겨 적기"라고 강조. 원장님들께 "예약 채널이 몇 개인가요?" 물어보기 — 보통 3~5개라 공감이 큼. 수강생 샵의 '옮겨 적기'를 1~2명에게 듣기.

API = 식당의 주문서 8분

식당에서 손님은 주방에 직접 들어가지 않습니다. 정해진 주문서에 메뉴·수량을 적어 내면, 주방이 음식을 내어 줍니다. 우리 샵의 상담 차트도 같아요. 정해진 칸(이름·관리 메뉴·피부 타입)을 채워야 관리사가 바로 일을 시작할 수 있죠.
API (에이피아이)
프로그램이 다른 프로그램에게 일을 부탁할 때 쓰는 정해진 주문서 양식. 양식대로 쓰면 결과를 돌려준다.
🙋손님= 부탁하는 프로그램
→
🧾주문서= API
→
👩‍🍳주방= Slack·Jira 같은 서비스
→
🍝음식= 결과
8~11회차에서 Claude가 Slack·Jira를 읽고 쓰는 것도, 결국 이 "주문서(API)"를 Claude가 대신 써 주는 것입니다. 어떻게 연결하는지는 잠시 뒤 MCP에서 봅니다.
"API를 직접 만들 일은 없다. 우리는 '주문서가 있다'는 것만 알면 된다"를 강조. 예상 질문: "API는 공짜인가요?" → 서비스마다 다름. 무료 한도가 있는 경우가 많고, Claude API처럼 쓴 만큼 내는 것도 있음(13~14회차). 예상 질문: "네이버 예약도 API로 자동으로 가져올 수 있나요?" → 일반 사업자에게 공개된 방법은 제한적이라 이 수업에서는 다루지 않음. 대신 네이버 예약 알림을 받은 사람이 Slack·Jira에 한 번만 옮기는 구조로 감(수업 전 확인).

웹훅 = 초인종 🔔 6분

🚪

초인종이 없다면

"다음 손님 오셨나?" 관리 중에도 5분마다 데스크에 나가 봅니다. 대부분 헛걸음이에요.

🔔

초인종이 있다면

손님이 도착하면 벨을 눌러 줍니다. 관리사는 하던 관리를 계속하면 돼요.

웹훅 (Webhook)
무슨 일이 생기면 상대 프로그램이 먼저 알려 주는 초인종. "문의가 들어오면 이 주소로 알려 줘"라고 미리 등록해 둔다.
13회차 LINE 상담봇이 바로 이 초인종 방식입니다. 일본인 손님이 「予約できますか」라고 보내면 LINE이 우리 봇의 초인종을 누릅니다.
"나가 보기" = 정해진 간격으로 확인(폴링). 용어는 소개하지 말고 그림만. Make·Zapier 무료 플랜이 "15분마다 확인"하는 이유가 이것(10회차 보너스에서 다시 나옴).

트리거 → 액션: 모든 자동화의 문장 6분

트리거 · 액션 (Trigger · Action)
트리거 = "~하면"(시작 신호), 액션 = "~한다"(이어서 할 일). 자동화는 전부 이 한 문장이다.
~하면 (트리거)만약 (조건, 선택)~한다 (액션)
매일 10:30이 되면화~일요일이면#스탠드업에 "오늘 예약 수·특이 고객" 질문 올리기 8회차
예약 카드가 "관리 완료"로 옮겨지면유형이 예약이면사후 연락 기한을 3일 뒤로 + #예약에 알림 10회차
손님이 LINE으로 질문하면AI가 "사람 필요"라고 하면 (트러블 호소 등)#cs-escalation 알림 + Jira 이슈 13회차
자동화하고 싶은 일이 생기면 먼저 "언제 ~하면, ~한다" 한 문장으로 말해 보세요. 문장이 안 나오면 아직 자동화할 때가 아닙니다.
수강생에게 "우리 샵의 ~하면 ~한다"를 하나씩 말하게 하기. 예: "예약 전날 18시가 되면 → 내일 예약 손님에게 리마인드 보낸다". 너무 큰 문장("예약이 오면 다 알아서")은 쪼개도록 유도. 손님에게 직접 가는 메시지 자동화는 개인정보·발신 규정 때문에 이 파트에서는 '팀 안' 알림부터 한다고 말해 두기.

API 키·토큰 = 우리 샵 열쇠 🔑 5분

주문서(API)를 아무나 쓰면 안 되겠죠? 그래서 서비스는 열쇠를 가진 사람의 주문만 받습니다. 열쇠를 가진 사람은 고객 카드 보관함을 열 수 있는 사람입니다.
API 키 · 토큰 (Key · Token)
"이 주문은 진짜 봄날 에스테틱이 보낸 것"임을 증명하는 긴 비밀 글자. 비밀번호와 똑같이 다룬다.
절대 공유 금지. 단톡방·Slack 채널·스크린샷·Claude 채팅창에 붙여넣지 마세요. 새 나가면 남이 우리 이름으로 메시지를 보내거나 요금이 나갈 수 있습니다. 유출이 의심되면 즉시 삭제(폐기)하고 새로 발급합니다.
10회차의 Slack 웹훅 주소, 13~14회차의 Claude·LINE 키도 모두 "열쇠"입니다. 비밀번호 관리 앱이나 종이 금고에 보관하세요.
가장 중요한 슬라이드. "고객 카드 보관함 열쇠를 단톡방에 올리는 원장님은 없다"로 기억시키기. 에스테틱은 피부 상태·알레르기 같은 건강 관련 정보를 다루므로 열쇠가 새면 피해가 더 큼(2회차 민감정보 복습). 예상 질문: "Claude에 붙여넣으면 안 되나요?" → 대화 기록에 남음. 코드에 넣을 땐 14회차에서 배우는 '비밀값 보관함'을 쓴다.

MCP = AI용 만능 콘센트 🔌 5분

해외여행 갈 때 챙기는 만능 어댑터를 떠올려 보세요. 나라마다 콘센트 모양이 달라도 하나면 다 꽂히죠. Claude도 Slack·Jira마다 주문서(API) 쓰는 법을 따로 배우지 않고, 공통 콘센트 하나에 서비스별 플러그를 꽂아서 씁니다.
MCP (엠씨피)
AI 앱이 Slack·Jira 같은 외부 서비스와 연결되는 공통 콘센트 규격. Claude 화면에서는 서비스별 플러그를 커넥터(Connector)라고 부른다.
🙋원장님 질문"오늘 #예약 요약해 줘"
→
🤖Claude콘센트 = MCP
→
🔌Slack 커넥터8회차에 꽂음
+
🔌Atlassian(Jira) 커넥터9회차에 꽂음
플러그를 꽂을 때 비밀 열쇠를 복사해 붙여넣지 않습니다. 서비스 화면에서 "허용" 버튼으로 출입증을 내주고, 언제든 회수할 수 있어요. 자세한 설정은 부록 F.
오늘은 "콘센트와 플러그" 그림만 기억하면 충분. 이름 풀이(Model Context Protocol)는 묻는 사람에게만. 공식 사이트도 "AI 앱용 USB-C 포트"라고 비유함(modelcontextprotocol.io). 실제 연결은 8회차(Slack), 9회차(Jira)에서 직접 해 봄. 메뉴 위치는 2026-10 기준 claude.ai Customize › Connectors. 예상 질문: "Claude가 우리 Slack을 다 보나요?" → 로그인한 내 계정이 볼 수 있는 범위만, 그리고 대화마다 켜고 끌 수 있음. 예상 질문: "열쇠(API 키)랑 뭐가 달라요?" → 키는 복사해서 보관하는 비밀 글자, 커넥터는 "허용" 버튼으로 받는 출입증. 그래도 출입증도 함부로 내주지 않는다는 원칙은 같음.

흰 칸 = 시작 · 주황 칸 = 사람 · 보라 칸 = 자동(프로그램)

화이트보드에 직접 그리며 설명하면 더 좋음. 색의 의미를 꼭 설명: 주황(사람)을 보라(자동)로 바꾸는 게 앞으로 7회의 목표. "모든 걸 자동으로"가 아니라 "사람이 꼭 필요한 곳만 사람"이 원칙. 특히 사후 연락(피부 상태 확인)과 트러블 상담은 끝까지 사람이 하는 칸 — 자동화는 "잊지 않게 알려 주는 것"까지. 봇은 예약을 확정하지 않고 네이버 예약 링크로 안내만 한다는 점도 미리 말해 두기(12~14회차).

실습 1 · 흐름도 그리는 법 (누가 → 무엇 → 어디로) 9분

  1. 종이에 우리 샵의 가장 자주 하는 일 1개를 고르기 (예: 예약 받기 → 사후 연락)
  2. 그 일의 단계를 포스트잇 한 장에 하나씩: 누가 → 무엇을 → 어디로
  3. 사람이 하는 칸은 주황, 옮겨 적기만 하는 칸에는 ⭐ 표시
  4. ⭐ 칸이 바로 자동화 후보입니다
  5. 그림을 사진으로 찍어 Claude에 올리고 아래처럼 부탁하기
첨부한 사진은 우리 에스테틱 샵의 예약 처리 흐름(예약 문의 → 예약 확정 → 전날 리마인드 → 관리 → 3일 뒤 사후 연락 → 재방문 안내)을 손으로 그린 거야. 1) 단계를 "누가 → 무엇을 → 어디로" 형식의 표로 정리해줘. 2) 사람이 같은 정보를 옮겨 적는 단계를 찾아서 표시해줘. 3) 그 단계를 "언제 ~하면, ~한다" 자동화 문장으로 바꿔줘. 4) 사후 연락·트러블 상담처럼 사람이 꼭 해야 하는 단계는 자동화하지 말고 "사람" 이라고 표시해줘. 모르는 부분은 추측하지 말고 질문해줘.
사진에 예약 노트·고객 카드(이름·전화번호·피부 질환·알레르기·임신 여부)가 찍히지 않게 하세요. 건강 관련 정보는 민감정보입니다.
손으로 먼저 그리는 게 핵심. 바로 Claude에 맡기면 우리 샵 사정(예약금, 24시간 전 변경 규정, 월요일 휴무)이 빠진 '일반적인 흐름'이 나옴. 사진 업로드가 어려운 수강생은 글로 단계 나열해도 됨. 데스크 위에서 찍으면 예약 노트가 같이 찍히는 경우가 많으니 빈 종이 위에서 찍게 하기.

한 일을 눌러서 체크하세요. (이 컴퓨터에 저장됩니다)

  • API를 "주문서"로, 웹훅을 "초인종"으로 설명할 수 있다
  • 자동화를 "언제 ~하면, ~한다" 문장으로 말할 수 있다
  • API 키·토큰은 절대 공유하지 않는다는 것을 안다
  • MCP를 "만능 콘센트", 커넥터를 "플러그"로 설명할 수 있다
  • 예약 문의부터 사후 연락까지 우리 샵 흐름도 1장을 그렸다
  • 자동화하고 싶은 일 3개를 사다리 칸에 놓아 봤다
