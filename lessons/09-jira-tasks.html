🤔 남은 고민

Slack에서 대화는 정리됐는데, "지난주 K님 사후 연락 드렸나?"는 여전히 스크롤해서 찾아야 합니다.

Slack = 대화하는 곳, Jira = 일의 상태를 보는 곳. 오늘은 두 번째를 만듭니다.
워크플로가 안 돈 수강생은 시간대·요일 설정을 바로 봐 주기(1~2분 이내). 과제로 가져온 "최근 예약 5건" 메모를 꺼내게 하기.

Jira = 데스크의 예약 카드 보드 8분

데스크 벽에 예약 카드가 한 장씩 꽂혀 있다고 떠올려 보세요. 예약이 확정되면 옆 칸으로, 관리가 끝나면 또 옆 칸으로, 사후 연락까지 끝나면 마지막 칸으로 옮겨집니다. 누가 보든 어떤 손님이 어디쯤인지 한눈에 보이죠.
이슈 (Issue)
예약 카드 한 장, 또는 고객 요청 한 장. 최근 화면에서는 작업 항목(Work item)으로 보일 수 있음
보드 (Board)
카드 꽂이 전체. 이슈 카드를 칸별로 늘어놓은 화면
상태 (Status)
꽂이의 칸. 접수 → 예약 확정 → 관리 완료 → 사후 연락 완료
담당자 (Assignee)
그 카드를 지금 들고 있는 사람. 한 이슈에 한 명
새 용어 4개. Atlassian이 2025년부터 "이슈"를 "작업 항목(Work item)"으로 바꾸는 중이라 화면과 슬라이드 용어가 다를 수 있다고 미리 말하기. 수업에서는 짧은 "이슈"로 통일. 예상 질문: "네이버 예약 관리 화면이 있는데 왜 또?" → 네이버는 '시간 칸'을 관리, Jira는 '관리 후 사후 연락·클레임·문의'까지 팀의 할 일을 관리. 4명이 동시에 보고, 옮길 때마다 알림이 가고, Slack·Claude와 연결되는 게 차이.

실습 1 · Jira Cloud 무료 가입 8분

  1. 크롬에서 atlassian.com → Jira → 무료로 시작(Get it free)
  2. Slack과 같은 샵 메일로 가입 → 메일 인증
  3. 사이트 이름 입력: 예) bomnal → 주소가 bomnal.atlassian.net이 됨
  4. 직무·팀 질문은 대충 고르거나 건너뛰기(Skip)
  5. 첫 화면(Jira 홈)이 보이면 성공 🎉 주소를 즐겨찾기
Free 플랜: 최대 10명, 저장 공간 2GB, 자동화 월 150 steps(10회차에서 계산). 봄날 에스테틱 4명이면 충분합니다.
사이트 이름은 나중에 바꾸기 어렵습니다. 샵 영문 이름으로 짧게 정하세요.

요금·한도·가입 화면은 2026-10 기준이며 바뀔 수 있습니다. 수업 전 강사가 최신 화면을 확인하세요.

막히는 곳: 가입 중 "Confluence도 같이 쓰기" 같은 추가 제안 → 건너뛰기. 사이트 이름 중복 → 뒤에 숫자나 지역 붙이기(bomnal-yeonnam).

실습 2 · 프로젝트 "봄날 에스테틱 운영" 만들기 8분

  1. 왼쪽 메뉴 프로젝트(Projects) → 프로젝트 만들기(Create project)
  2. 템플릿에서 칸반(Kanban) 선택 → 템플릿 사용
  3. 유형은 팀 관리형(Team-managed) 선택 (설정이 쉬움)
  4. 이름: 봄날 에스테틱 운영 / 키: BOM
  5. 만들기 → 보드 화면이 열리면 성공
키(BOM)는 카드 번호의 앞글자입니다. 이슈가 BOM-1, BOM-2처럼 번호가 붙어요. 10·13회차 자동화가 이 키를 씁니다.
최근 화면에서는 "프로젝트"가 스페이스(Space)로 보일 수 있습니다. 같은 것입니다.
키는 자동으로 제안되니 BOM으로 직접 고쳐야 함. "회사 관리형(Company-managed)"을 고른 경우 설정 메뉴가 달라짐 → 새로 만드는 게 빠름.

실습 3 · 보드 칸을 우리 샵 순서로 바꾸기 7분

📥접수To Do
→
📅예약 확정In Progress
→
💆관리 완료새로 추가
→
📞사후 연락 완료Done
  1. 보드에서 열 제목 To Do(할 일)에 마우스 → ⋯ → 이름 바꾸기 → "접수"
  2. In Progress → "예약 확정", Done → "사후 연락 완료"
  3. 열 오른쪽 끝 + 버튼 → "관리 완료" 추가 → 끌어서 예약 확정과 사후 연락 완료 사이로
"관리 완료"는 끝이 아닙니다. 3일 뒤 피부 상태를 여쭤보고 나서야 사후 연락 완료 — 그때 카드가 진짜 끝납니다.
"관리 완료" 열은 10회차 자동화 기준이 되니 이름을 정확히(띄어쓰기 포함). 새로 추가한 열은 '진행 중' 계열 상태가 되는 게 정상 — 마지막 "사후 연락 완료"만 완료(Done) 계열이어야 함. 열 이름은 나중에 바꿔도 되지만 10회차 규칙을 만든 뒤에 바꾸면 규칙도 고쳐야 함.

실습 4 · 이슈 유형 만들기: 예약 · 문의 · 클레임 7분

  1. 왼쪽 아래 프로젝트 설정(Project settings) → 이슈 유형(Issue types)
  2. 이슈 유형 추가(Add issue type) → 이름 "예약", 아이콘 고르기
  3. 같은 방법으로 "문의", "클레임"
  4. "예약" 유형에 기한(Due date)·라벨(Labels) 필드가 있는지 확인 → 없으면 오른쪽 필드 목록에서 끌어다 놓기
  5. 저장(Save changes)
유형예시누가 주로
예약수분 진정 관리 · 10/14(화) 15:00민호 → 지수·유나
문의"회원권 남은 횟수 가족이 써도 되나요?"민호·원장
클레임관리 후 붉어짐 호소 → 원장이 직접 연락원장

화면에 따라 "작업 유형(Work type)"으로 보일 수 있습니다.

유형 이름은 13회차 봇(클레임/문의 이슈 자동 생성)과 같아야 하므로 정확히 "예약/문의/클레임". 약속: 기한(Due date) = "이 카드로 다음에 할 일의 날짜" — 예약 확정 때는 관리일, 관리 완료 뒤에는 사후 연락일(10회차 자동화가 바꿔 줌). 그래서 관리 날짜는 요약에도 꼭 적는다. 라벨은 "노쇼" 표시에 씀(11회차 주간 보고).

칸을 옮길 때 담당자도 같이 바꾸는 것이 핵심입니다. "지금 이 카드를 들고 있는 사람"이 늘 보이게요.
노쇼라면? 라벨에 노쇼를 달고, 예약금 처리 메모를 댓글로 남긴 뒤 바로 "사후 연락 완료"로 옮깁니다. 10회차에서는 "관리 완료"로 옮기면 3일 뒤 사후 연락 기한이 자동으로 잡히게 만듭니다.
강사 보드에서 카드를 실제로 끌어 옮기며 시연. 카드를 클릭해 상세(설명·담당자·기한·라벨·댓글)도 보여 주기. 노쇼 규정 복습: 24시간 전까지 무료 변경·취소, 이후 취소·노쇼는 예약금 10,000원 환불 불가, 회원권은 1회 차감.

실습 5 · 예약 이슈 만들고 옮기기 9분

  1. 위쪽 + 만들기(Create) → 프로젝트 BOM, 유형 예약
  2. 요약: [예약] 트러블 케어 · 10/14(화) 15:00 · K님
  3. 설명에 오른쪽 양식 붙여넣고 채우기
  4. 담당자: 지수 / 기한: 관리일 → 만들기
  5. 과제로 가져온 예약 5건도 같은 방법으로
  6. 보드에서 카드를 예약 확정 → 관리 완료 → 사후 연락 완료로 끌어 옮겨 보기 (1장은 라벨 노쇼로 연습)
관리: 여드름·트러블 케어 70분 (90,000원)
일시: 10/14(화) 15:00 / 담당 관리사: 지수
손님: K님 (첫 방문 / 회원권 잔여 ○회)
예약 경로: 네이버 예약 / 예약금 10,000원 확인
메모: 주의사항 있음 → 고객 카드 확인
전화번호·실명 전체, 피부 질환·알레르기·임신 여부·복용 약은 적지 마세요. 건강 관련 민감정보입니다. "고객 카드 확인"으로만 남기고, 원본은 샵의 고객 카드에 둡니다. 이 보드는 이후 Claude도 읽습니다.
손님은 이니셜 또는 성만. 회원권 잔여 횟수 같은 영업 정보는 적어도 됨(4회차 회원권 표와 연결). 원장님들이 "알레르기는 관리사가 꼭 알아야 하는데요?"라고 많이 물음 → 관리사는 관리 전에 고객 카드를 직접 보는 규칙으로. Jira·Slack·AI에는 "주의사항 있음" 신호만.

실습 6 · Claude에 Jira 플러그 꽂기 (Atlassian 커넥터) 8분

  1. claude.ai → Customize(사용자 지정) › Connectors(커넥터) › Discover → Atlassian 검색
  2. 만든 곳이 Atlassian인 커넥터(Atlassian MCP / Rovo) 클릭 → Connect to Claude
  3. Atlassian 계정(Jira 가입한 샵 메일)으로 로그인
  4. 사이트 선택에서 bomnal.atlassian.net 고르기
  5. 요청 권한(Jira 읽기·이슈 만들기·수정 등) 확인 → Accept(수락)
  6. Connected 확인 → Atlassian › Tool permissions: 읽기·검색 Always allow, 만들기·수정·댓글 Needs approval
사이트 관리자(원장님)가 먼저 연결하세요. 첫 연결 때 우리 Jira 사이트에 Claude 연결이 등록됩니다. 직원은 그다음에 각자 연결하면 돼요.
권한은 Jira 설정 그대로예요. 내가 못 보는 프로젝트는 Claude도 못 보고, 내가 못 만드는 이슈는 Claude도 못 만듭니다.
Slack 연결(8회차)과 같은 화면, 같은 순서예요. 플러그만 하나 더 꽂는 거라고 생각하세요.

2026-10 기준. 수업 전 확인: 커넥터 표시 이름, Jira Free 포함 여부·시간당 호출 한도(Free 약 500회로 알려짐), 첫 연결을 사이트 관리자가 해야 하는지. 자세히는 부록 F.

공식: Atlassian Rovo MCP 서버, Cloud 사이트만(Data Center/Server 불가), OAuth 로그인, 사용자의 기존 Jira 권한 그대로. 권장 주소 https://mcp.atlassian.com/v2/mcp — 옛 자료의 /v1/sse 주소는 2026-06-30 지원 종료라 쓰지 말 것(디렉터리 커넥터는 주소 입력 없이 클릭). 첫 사용자가 동의하면 사이트에 자동 설치되어 Atlassian Administration › Apps › Sites › 사이트 › Connected apps에 표시됨. "관리자가 먼저"는 비공식 권장 — 수업 전 확인. 막히는 곳: ① 다른 Atlassian 사이트 선택 → Disconnect 후 다시 ② 연결이 막힘 → Atlassian Administration › Rovo › Rovo MCP server의 "Allow Atlassian supported domains"가 꺼져 있는지(조직 관리자만 변경) ③ 팝업 차단.

실습 7 · Claude에게 BOM 이슈 만들기 맡기고 보드에서 확인 8분

  1. 새 채팅 → 입력창 + › Connectors → Atlassian 토글 ON
  2. 연결 테스트: "내가 볼 수 있는 Jira 프로젝트 알려 줘" → BOM이 나오면 OK
  3. 오른쪽 프롬프트 실행 → Claude가 보여 주는 표 확인 → "좋아"
  4. 이슈 만들기 승인 창 → 내용 읽고 Allow once
  5. Jira 보드 새로 고침 → 카드 5장(BOM-○○)이 생겼는지, 유형·기한·상태가 맞는지 한 장씩 클릭해 확인
  6. 틀린 카드는 Jira에서 직접 고치기 (지우기는 사람이)
Jira BOM 프로젝트에 내일 관리할 "예약" 유형 이슈 5개를 만들어줘. 요약 형식: [예약] 관리 메뉴 · 날짜(요일) 시간 · 손님 이니셜 기한: 내일 날짜, 상태: 예약 확정, 담당자는 비워 둬. 1) 수분 진정 관리 · 11:00 · K님 2) 리프팅 탄력 관리 · 13:00 · P님 (회원권) 3) 첫 방문 체험 · 14:30 · L님 4) 등 관리 · 16:00 · C님 5) 여드름·트러블 케어 · 18:00 · J님 만들기 전에 표로 먼저 보여주고, 같은 시간에 겹치는 예약이 있으면 알려줘. 내가 "좋아"라고 하면 만들어줘.
AI가 만든 이슈는 한 장씩 확인하세요. 날짜·유형·시간이 틀릴 수 있습니다. 내일이 월요일(휴무)이면 날짜를 바꿔서 실행하세요. 건강정보는 프롬프트에도 넣지 않습니다.
"표로 먼저 보여 주고 승인 후 실행" + Needs approval 승인 창 = 이중 안전장치. AI에게 쓰기 권한을 줄 때의 기본 습관이니 꼭 따라 하게 하기. 막히는 곳: 이슈 유형 "예약"을 못 찾음(실습 4 미완료), 상태 "예약 확정"으로 바로 못 만들고 "접수"로 생김 → 손으로 옮기거나 "BOM-○○을 예약 확정으로 옮겨 줘"로 연습, 보드에 안 보임 → 보드 필터·다른 프로젝트 확인. 빨리 끝난 수강생: "BOM 프로젝트에서 담당자 없는 예약 이슈 목록 보여 줘"(읽기)로 검색도 연습.

응용 실습 · 우리 샵 보드 설계하기 4분

나는 ○○(업종)을 운영하고 직원은 ○명이야. Jira 칸반 보드를 설계해줘. 1) 보드 칸(상태) 4~5개: 우리 일의 실제 순서대로 (관리 후 사후 연락처럼 "끝난 뒤 할 일"도 포함) 2) 이슈 유형 3개와 각각의 예시 3) 이슈 요약 작성 규칙 한 줄 (예: [유형] 내용 · 날짜 시간 · 이니셜) 개인정보·건강정보를 이슈에 적지 않는 규칙도 한 줄 넣어줘.
칸은 "누가 손에 들고 있나"가 바뀌는 지점에서 나누세요. 봄날 에스테틱은 데스크(접수·확정) → 관리사(관리) → 데스크(사후 연락) 순서라 4칸입니다.
자기 샵 보드는 지금 만들 필요 없음. 설계표만 저장. 에스테틱이 아닌 수강생(네일·헤어·필라테스 등) 예시를 하나 같이 풀어 주면 좋음 — 대부분 "예약 → 서비스 → 사후 관리" 구조라 그대로 응용됨.
