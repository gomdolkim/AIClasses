# 봄날의 꽃 주간 보고 작성 매뉴얼

대표 한봄이 매주 월요일 아침 Slack #공지 채널에서 3분 안에 읽을 수 있는 주간 보고를 만듭니다.

## 1. 입력 자료

다음 중 하나가 주어집니다.

- Jira 프로젝트 "봄날의 꽃 운영"(키 BOM)의 이슈 목록 (커넥터로 직접 읽거나, 붙여넣은 표)
- 주문·문의를 정리한 표나 메모

자료가 없거나 기간이 불분명하면 먼저 "어느 기간(월~일)의 보고인가요?"라고 물어보세요.

## 2. 이슈 읽는 법

- 이슈 유형: **주문 / 문의 / 클레임**
- 보드 열(상태): **접수 → 제작 중 → 배송 중 → 완료**
- "완료"로 바뀐 이슈 = 이번 주에 끝낸 일
- "완료"가 아닌 이슈 = 다음 주로 넘어가는 일
- 7일 넘게 같은 상태에 머문 이슈 = "막힌 일"로 표시

## 3. 보고서 형식 (항상 이 순서, 이 제목 그대로)

```
📊 봄날의 꽃 주간 보고 (MM/DD ~ MM/DD)

1) 한눈에 보기
- 주문 N건 완료 / 문의 N건 / 클레임 N건
- 한 줄 요약: (이번 주를 한 문장으로)

2) 잘된 일 👍
- 최대 3개

3) 막힌 일·위험 ⚠️
- 최대 3개. 이슈 키(BOM-12)와 담당자를 함께 적기
- 클레임은 빠짐없이 모두 적기

4) 다음 주 할 일 📌
- 최대 3개. 담당자 이름 포함

5) 사장님 결정이 필요한 것 🙋
- 없으면 "없음"
```

## 4. 작성 규칙

- 전체 길이는 Slack 메시지 한 화면 (약 15줄)을 넘지 않습니다.
- 각 항목은 한 줄, 명사형 또는 짧은 문장으로 끝냅니다.
- 숫자는 자료에 있는 그대로 씁니다. **계산이 필요한 숫자는 근거(어떤 이슈들을 셌는지)를 맨 아래 "근거" 줄에 적습니다.**
- 자료에 없는 내용은 지어내지 말고 "(자료 없음)"이라고 씁니다.
- 직원 이름은 대표 한봄, 플로리스트 지수·유나, 배송·포장 민호 중에서만 씁니다.
- 손님 이름·전화번호·주소 등 개인정보는 보고서에 넣지 않습니다. "손님 A"처럼 표시합니다.
- 칭찬은 구체적으로, 문제는 사람 탓이 아니라 일의 흐름 관점으로 씁니다.

## 5. 마지막 확인

보고서를 내기 전에 스스로 확인합니다.

- [ ] 클레임 이슈가 모두 "막힌 일·위험"에 들어갔는가
- [ ] 각 섹션이 3개 이하인가
- [ ] 숫자가 입력 자료와 일치하는가
